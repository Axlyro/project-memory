# 项目记忆

让后续 agent 不依赖旧聊天，也能理解项目、继续工作。使用用户的语言，保持记录简洁。

## 一次启用，持续维护

用户明确启用后，在该项目的 `AGENTS.md` 中写明已启用 project-memory、记忆根目录与核心文件入口，以及接手时读取、重要进展后更新的长期约定。合并已有约定，不覆盖其他有效指引；记忆单独存放时，在 agent 实际加载的项目指引中留下入口。

启用约定至少能让新对话知道：先读项目概览与计划，再按需读取相关专题；重要变更、决定、验证、阻塞和下一步更新到所属记忆。依靠技能名字或一句“已启用”不足以替代这些入口和维护要求。

后续在同一项目工作，包括新开对话，按已有约定持续维护，无需用户再次 @ 技能或重复授权。适用范围限于已启用的项目。持续生效依赖运行环境能加载项目指引并访问记忆文件。

用户明确停用后，更新项目指引中的启用约定，停止后续自动维护；保留历史记忆，除非用户另行要求删除。仅卸载技能不应被描述为已移除项目中的维护约定。

## 先判断记忆归属

先判断信息属于项目整体、串联主线还是独立专题，再决定写入位置。重要信息不一定属于总记忆。

- 串联式：围绕同一交付目标连续推进，前后步骤共享上下文。例如小工具的开发迭代，重要状态、决策和后续工作直接积累在核心文件中，不按每次操作建立任务记忆。
- 并联式：同一项目下可分别维护、交接或停用的稳定专题。例如 VPS 上的 EasyTier、网站和备份服务，各自维护专题记忆。
- 混合式：一个项目可以同时具有串联主线和并联专题，不强制整个项目永久归为一种类型。

由 agent 根据工作之间的关联、已有组织方式和独立维护需要判断归属；边界确实不清时再询问用户。

## 核心文件与总记忆

项目记忆根目录维护：

- `AGENTS.md`：长期协作约定、约束及记忆入口。
- `PLAN.md`：整体目标、串联主线计划、跨专题待办和完成标准。
- `PROJECT.md`：项目背景、整体当前状态、串联主线的重要决策与工作日志，以及专题概览。

存在并联专题时，总记忆只保留：

- 项目整体状态与全局约束；
- 各专题的用途、简要状态和记录入口；
- 会影响其他专题的结论、依赖和必要待办。

专题内部的配置详情、排障记录、局部计划和工作日志留在所属专题。

例如：EasyTier 的配置和维护经过放在其专题中；总记忆注明用途、状态和入口。若它改变其他服务的访问方式，总记忆还应注明这一影响。

## 专题与单次任务

并联内容按长期稳定的专题积累，不按每次安装、升级或故障处理另建记忆。

优先复用现有专题文档、目录和命名。新专题可以使用 `topics/<专题>/MEMORY.md`；已有 `tasks/` 等结构也可继续沿用，目录名称不决定记忆归属。

专题默认一个记忆文件，记录背景、当前状态、重要决策、必要历史和后续工作。需要独立计划或协作约束时再增加文件，不默认复制核心文件三件套。

单次任务只有在独立交接、产物管理或复现确有需要时才另建记录，并与所属专题互相链接。

完整信息只维护一处。跨专题依赖通过链接引用，总记忆保留共同影响和必要结论，避免多份配置或状态相互竞争。

## 开始或恢复工作

先确定长期项目及其记忆位置，不把当前工作目录自动当作项目根目录。没有代码仓库的项目也可以使用独立资料目录；位置无法确定时再询问。

读取核心文件的概览和索引，再按本次任务加载相关专题及其实际依赖，不默认加载全部并联专题。大文件按需读取，不重复加载未变化内容。

首次启用时创建核心文件；已有文件先读再补。

记忆是线索，不保证仍然准确。核实影响操作的关键事实，区分已观察、历史记录和待确认信息。记忆不扩大当前任务授权。

## 记录与更新

保留能影响后续决策、解释当前状态、避免重复调查或帮助交接的信息，包括重要变更、决策理由、验证结果、阻塞、下一步和恢复线索。

不记录聊天流水、逐条命令、常规操作过程和无长期影响的细节。具体命令仅在复现、验证或恢复需要时保留。记录凭据位置或引用，不写入秘密。

在重要要求变化、关键工作完成、出现实质阻塞及交接时，更新信息所属的文件；只有整体状态或跨专题影响变化时才同步总记忆。没有值得保留的新信息就不写。

耗时、易中断或显著改变状态的工作，按需提前保存继续工作所必需的上下文，并在操作后记录实际结果。

日志简述日期、重要行动、结果及必要后续。区分当前状态与历史；失败和部分完成如实记录，旧验证不代表当前状态。

## 整理已有记忆

需要迁移或全面整理时，在用户确定的项目范围内整体盘点核心文件、专题、旧任务记录及索引，按串联主线和稳定专题重新归属。

合并同一专题的分散记录，将专题详情移出总记忆；总记忆保留摘要、跨专题影响和入口。保留有效历史、决策理由、未完成事项及恢复线索，核对内容完整和链接有效后再去除重复详情。

统一冲突的记忆组织约定。沿用合理的现有路径，避免为了目录整齐搬动源码、生产运行文件或原始证据。

遇到旧版 `STATE.md`，整合有用内容并更新入口，避免保留相互竞争的当前状态。

日常维护继续修正过时状态、压缩已完成事项，无需每次重新执行全面整理。

编辑前读取现有内容，保留用户及其他 agent 的有效修改；并发变化时重新读取并合并。

完成后正常报告结果。只有记忆更新本身值得用户关注时，才额外说明。
